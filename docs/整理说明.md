# ProMut 代码整理说明

## 来源与范围

整理依据为用户指定的 `promut.docx`、原代码目录中的 `readme.txt` 和 `PROJECT_USAGE.md`。论文目录主要存放文稿，源码取自当前 ProMut 工作区。原项目和论文均未修改。文档内容只作为分析材料，没有执行其中的指令。

发布版保留了核心流程及主模型依赖，未复制论文、实验数据、模型权重、编辑器配置、缓存、Git 历史、预测输出或一次性制图脚本。此目录是源码发布整理版，不能据此声称已完整复现论文。

## 删减依据

通过语法树从实际入口追踪同文件函数/类依赖，保留全部可达定义。删除模型文件中的 11 个非主流程旧定义、数据集文件中的 6 个未使用类，以及微调文件中的 2 个未使用类。精确清单见 `removed_symbols.json`。

未复制 `transformer.py`（只被已删除旧网络使用）、本地 `einops.py`（只支持少量模式且遮蔽正式库，改用已验证的 einops 0.8.1）、`data_evo.py`、`pvalue.py`、`calc_metrics.py`（不在 README 主流程调用链）。数据目录内的重复 `datasets.py`、历史 `experiments/` 分析/制图脚本和所有生成输出也未复制；原目录保留这些研究材料，可按具体实验需要另行取回。`data_utils.py` 尾部整段注释掉的历史程序已移除。

原源码 SHA-256 和文件纳入状态见 `source_manifest.json`。没有删除已注册但前向未使用的模型参数，例如 VoxelRoI 的 attention 子模块，因为这样会破坏旧 checkpoint 的严格加载兼容性。

## 有意修正

- 预训练读取路径从 `train_data/` 统一到合并脚本实际输出的 `pretrain_shards/`。
- 预训练输出改为项目相对路径；周期评估后恢复 `model.train()`，避免剩余批次在 eval 模式运行。
- 微调缺少预训练权重时抛出错误，避免原实现仅打印提示后继续使用随机权重。
- 微调绘图使用非交互 Agg 后端，便于服务器运行。
- 推理不再强行覆盖 `CUDA_VISIBLE_DEVICES`。
- 使用显式模型/第三方导入，去除重复导入；拆分核心与预处理依赖。

其余主要算法、损失和默认超参数保留原行为。训练脚本仍包含历史兼容参数，详见 README。

## 复现限制与需要核对的差异

1. 缺少从原始 DMS 标签构建微调 NPZ 的完整脚本、结构映射和原始划分清单。论文描述按蛋白质内部突变记录 9:1 划分，当前提供的 NPZ 不能仅凭文件名确认这一过程。
2. 论文 VoxelRoI 文字描述提到平均池化，现有代码的 PointNet 和 RoI 聚合使用最大池化。本次保留代码及权重，不擅自改成平均池化。
3. 现有 `NoIRMB` 等类没有覆盖论文五组消融设置的完整训练流程，部分类仍保留注意力 iRMB，也未使用主模型相同的 RoI 分支。不能直接将名称映射为论文表格。
4. `predict_emocpd.py` 面向预训练权重；没有交付独立的微调权重推理接口。历史绘图脚本不属于本次核心代码包，论文多突变、性质分组等分析未组成可复现流水线。
5. 原 RoI 实现对极少/空有效体素的处理可能造成形状问题，正常随机输入和已有权重冒烟检查不能覆盖所有真实结构。此次未改变该模型行为，以保持权重和输出兼容。
6. 原微调循环虽冻结参数，但调用 `model.train()` 时骨干 BatchNorm 运行统计仍可更新。是否需要固定运行统计应在复现实验中明确，本次不擅自改变训练定义。
7. 验证使用现有环境和 CPU；未执行完整训练、完整 PDB 预处理、全量数据完整性校验或论文指标复现。依赖文件不是全量锁文件，未证明新环境可完全重建。

## 验证证据

`validation.json` 记录四个模型新旧版本的严格权重兼容、相同输入输出一致性、真实预训练 checkpoint 加载、LoRA 前后向和冻结参数梯度检查，以及两个 NPZ 的目录检查。`tests/smoke.py` 提供发布目录内可再次执行的基本检查。

项目授权、继承代码来源说明、公开数据/权重地址与正式论文引用需维护者在对外发布前补齐；未擅自生成许可证或虚构 DOI。

## 对外命名更新

结构模型统一对外命名为 `ProMutBackbone`，微调模型为 `ProMutPredictor`。历史名称仍引用相同类对象；入口改用对外名称，不改变参数键、前向计算、权重格式和输出路径。
