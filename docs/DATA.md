# 数据接口

## 预训练

`generate_full_sidechain_box_20A.py` 将残基的局部环境编码为 7×20×20×20 体素，保存键名 `arr`。`build_pretrain_shards.py` 将其合并并保存为默认键 `arr_0`；`NpzDataset` 读取数据和标签文件的 `arr_0`。20 类的顺序由 `atom_res_dict.py` 决定，不应改成字母排序。

原代码按残基类别分别合并并依次训练，这不等价于随机混合样本的数据分片。为避免在整理中改变训练方法，本次保留该行为。

## 微调

训练和验证 NPZ 均需要下列键：

| 键 | 内容 |
|---|---|
| `data` | 体素，形状 `[N,7,20,20,20]` 或 `[N,1,7,20,20,20]` |
| `positions` | 残基位置 |
| `protein_names` | 蛋白质标识 |
| `mutation_labels` | 每个位点的真实突变评分 |
| `mutation_types` | 与评分对应的氨基酸类型索引 |
| `ranked_types` | 氨基酸排序信息 |

后面五个数组必须与体素样本一一对齐；每个位点的突变评分/类型可为变长数组。加载器使用 `allow_pickle=True`，应使用来源可信的数据文件。评分方向遵循原 README：数值越大表示突变越好。

原始标签文件 `gym_single.csv` 和 `dms_single_fix.csv` 不是这两个 NPZ 的替代品。重建数据还需要明确结构映射、残基编号、链号、突变过滤、排序以及划分规则；现有代码不能完整恢复这些步骤。

整理时读取了本地两个 NPZ 的 ZIP 中央目录，均包含上述六个键；这只证明文件目录可识别，未对全部压缩成员做 CRC 校验或完整加载。旧使用说明中关于训练文件损坏的记录未被本次轻量检查复现。
